**応答の読み方と、書き込みの値の変換の不具合を直しました。**

- **崩れた応答を、成功として読まなくなりました。** 応答の `<Code>` が数でない・入れ子になっている・2 つある、書き込みの応答で件ごとの `<Code>` が無い、成功した件に `<Id>` が無い、といった応答は `PortersResourceError`（`category: "unknown"`）になります。これまでは成功や id `0` として読むことがありました。書き込みの応答も、書き込んだリソースの名前のルート要素であることを確かめます。1 件の書き込みに複数の結果が返ったときもエラーになります。
- **XML の属性が値に混ざらなくなりました。** 読むのはルート要素の属性（`Total` など）だけです。
- **値の前後の空白と改行が消えなくなりました。** 複数行テキストを読んで書き戻しても、値が変わりません。空白だけの値は、`null` ではなくその空白のまま返ります。数値文字参照（`&#12354;` など）も文字に直して返します。
- **ユーザー・部署・参照の項目の `P_Id` が空なら `null` を返すようになりました。** これまでは `0` を返していました。数でない値は、項目名付きのエラーになります。
- **書き込みで、`NaN`・`Infinity`・指数表記の数（`1e21` など）を送らなくなりました。** id の項目（ユーザー・参照など）は整数に限ります。どちらも送る前に `PortersConfigError`（`category: "validation"`）になります。
- **`Date` / `Age` の書き込みで、暦に無い日付や、日付の後ろに別の文字が続く値を送らなくなりました。** 時刻とゾーンのある値は、UTC に直した日付として送ります（これまではゾーンを無視して日付の部分を送っていました）。

`createMockTransport` などで自前の偽の応答を返しているテストは、書き込みの応答のルート要素が書き込んだリソースの名前でない（例: どのリソースにも `<Candidate>` を返す）と、エラーになります。
