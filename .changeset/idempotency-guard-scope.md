**適用されていないと分かっている失敗**では `create` / `createMany` が自動リトライされるようになりました（RV-22 / ADR-0063）。

非冪等な書き込みを不確定な失敗で再送しない方針（二重登録を作らない）は変わりません。変えたのは「不確定」の判定で、
これまでは `PortersNetworkError` かどうかだけを見ていたため、**リクエストが一度も出ていない失敗**まで
「適用されたかもしれない」扱いになっていました。

- **トークン取得に失敗した場合** — 送信前なので再送しても二重登録は起きません。自動リトライの対象になります。
- **HTTP 429** — 処理される前に拒否された応答なので、同じく対象になります
  （実 PORTERS はレート超過で切断する想定なので、効くのはプロキシ経由の環境です）。

**送信後の timeout / 切断 / 5xx では、従来どおり再送しません**（適用されたかどうか分からないため）。
公開型・公開 API に変更はありません。
