書き込みの alias が **XML の名前として妥当か**を送信前に検査するようにしました（ADR-0085 / RV-48）。

PORTERS は Option の値を**タグ名**として書きます（`<FieldAlias><OptionAlias/></FieldAlias>`）。
これまでその値を検証せずそのまま埋めていたため、選択肢 alias を外から受け取っていると、
**XML の構造として解釈される**文字列を渡せてしまいました。結果として
**呼び出し側が指定していないレコードが書き換わる**ことがあります。

```ts
// これまで: userInput 次第で、10001 ではない別レコードが更新されることがあった
await t.candidate.update(10001, { P_Phase: [userInput] });
// これから: 不正なら送信前に PortersConfigError（category: "validation"）
```

- 通るのは **XML の `Name`**（英数字・`_`・`-`・`.`・日本語など。先頭に数字や `-` は置けません）。
  出典が alias の書式を定めていないので、**XML が許すものはすべて許します** —
  `Option.P_東京` のような alias も従来どおり書けます。
- 同じ検査が**項目 alias**（書き込み入力のキー）にもかかります。`JSON.parse` したオブジェクトを
  そのまま渡す場合、型はキーを検査しきれないためです。
- **本文になる値（テキスト項目など）の扱いは変わりません。** これまでどおりエスケープされます。

正しい alias を渡していたコードは無変更です。エラーになるのは、これまで**不正な XML を
送っていた**呼び出しだけです。
