**通信と認証まわりの不具合を直しました。**

- **送った後に失敗した `create` のエラーが、`retryable: false` で届くようになりました。** これまでは接続エラーのとき `retryable: true` のまま届き、`retryable` を見て再送すると二重登録になるおそれがありました。`hint` に「登録された可能性がある」ことが書かれ、元のエラーは `cause` にあります。PORTERS が Code 302 を返したときも、`create` は自動で再送せず、同じ形で届きます（Code 9 は今までどおり再送します）。
- **内蔵のスロットルが、起動直後の 1 分間に上限を超えて送ることがなくなりました。** これまでは最初の 60 秒で Read を最大約 3600 件送ることがありました。直近 60 秒に送った時刻を覚え、どの 60 秒を切り取っても上限の 90%（既定）を超えない形にしました。`createThrottle` の設定は変わりません。時間は戻らない時計（`performance.now()`）で測ります。
- **同時に届いたトークン切れ（401 / 402）で、トークンの取り直しが 1 回にまとまるようになりました。** 起動直後に同時に呼んだときも、保存済みのトークンがあれば新しく取得しません。
- **HTTP のリダイレクトを追いかけなくなりました。** これまでは 3xx の先へ Access Token や App Secret を送っていました。3xx はエラーとして届きます。
- **`createFetchTransport` の `timeoutMs` は 2,147,483,647 までになりました。** これを超える値では、すべてのリクエストがすぐ中断されていました。超える値は構築時に `PortersConfigError` になります。
