**読み書きの共通の仕組みの不具合を直しました。** 今まで黙って誤った結果を返していた入力や応答は、送る前、または受け取った時点でエラーになります。

- **`update(-1, …)` が、更新ではなく新規作成になっていました。** PORTERS では書き込みの id `-1` が新規作成を意味するためです。`update` / `updateMany` / `get` / `getMany`（添付ファイルの `update` / `get` も）の id が 1 以上の整数でなければ、送る前に `PortersConfigError` になります。JavaScript から文字列の id（`"10001"` など）を渡した場合も同じです。
- **条件の値にカンマがあると、値の途中から別の条件として読まれていました**（例 `P_Name: { part: "山田,…" }`）。PORTERS には値の中のカンマを書く方法が無いため、条件の値のカンマ、`or` / `and` の値のカンマとコロン、キーワードのカンマは、送る前に `PortersConfigError` になります。`or` / `and` の空の配列、知らない演算子、カンマ・コロン・等号を含む項目名、0 以上の整数でない `start` も同じです。テキストや日時の値のコロンは拒否しません。
- **`createMany` が途中のバッチで止まったとき、`hint` に再送の判断に要ることを書くようになりました。** これまでは、先のバッチで断られたレコードの情報が失われ、「この index 以降を再送」という案内に従うと、そのレコードが抜けたり、結果の分からないバッチが重複したりしました。`hint` に、失敗したバッチの範囲（書き込まれた可能性があるか）・まだ送っていない範囲・先のバッチで断られた index を書きます。
- **`searchAll` が、応答の件数の属性（`Total` など）が無いときに 1 ページで黙って終わることがなくなりました。** 応答が頼んだページと合わないときも、同じレコードを繰り返し返さずに止まります（`PortersResourceError`）。
- **`get` / `getMany` が、切れた応答や別のレコードを「頼んだレコード」として返すことがなくなりました。** 返ってきたレコードの件数・重複・id を頼んだ id と突き合わせ、合わなければ `PortersResourceError` になります。

`createMockTransport` などで自前の偽の応答を返しているテストは、`get` に一覧（2 件以上）を返していたり、`searchAll` の 2 ページ目以降も `Start="0"` を返していたりすると、エラーになります。本物の PORTERS と同じく、`get` には条件に合う 1 件を、各ページには要求した `start` を返してください。
