# 入力と経路の棚卸し、および当てる壊れ方

「その場で気づいたことを書く」レビューは、気づかなかったものを取りこぼす。ここは**気づきに頼らずに当てる表**。§1 で何を信じているか / どこを通るかを列挙し、§2 の壊れ方を機械的に当てる。**この 2 つは対象非依存**で、シェルでも TypeScript でも同じように使う。過去に実際に出たバグクラスは対象ごとに分けてある（§3）。

---

## 1. 信じている入力の棚卸し

まず「このコードが正しいと信じて受け取っているもの」を全部書き出す。**書き出せていない入力は、検証もされない。**

**1 行 = 1 つの値**に割る。「レポートの機械可読 3 行」のようにまとめて 1 行に数えると、**その中で検証済みの値と未検証の値が混在していることが表に現れない**。下は実例で、3 行目だけが空欄になる:

| # | 値 | 出どころ | 誰が書けるか | 事実と突き合わせているか | 失敗時の振る舞い | 記録される理由は事実か |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 判定の指紋 | LLM が書いた本文 | Issue を編集できる人 | 済 — gate が渡す `EXPECTED_FINGERPRINT` と比較 | 不一致なら投稿前に落ちる | 済 — 期待値を文面に出す |
| 2 | 取り込み対象の head SHA | LLM が書いた本文 | 同上 | 済 — gate が渡す `EXPECTED_PR_HEADS` と比較 | 不一致なら投稿前に落ちる | 済 — 期待値と実際を並べる |
| 3 | 検査時刻 | LLM が書いた本文 | 同上 | **未 — 形式しか見ていない** | 未来の値だと 3 日ルールが無言で永久に効かない | — |
| 4 | 判定時点の head SHA（取り込み時） | レポートの取り込み対象行 | 同上 | 済 — `merge-base --is-ancestor` | 祖先でなければ中断 | **未 — 未フェッチ / 空 / 本当の force-push が同じ文言** |

列の意味:

- **出どころ** — 人が手で書くのか、別ジョブから渡るのか、外部 API か、リポジトリ設定か。
- **誰が書けるか** — public リポジトリなら Issue もタイトルもラベルも第三者が作れる。**「自分たちしか書かない」は前提として弱い。**
- **事実と突き合わせているか** — **形式の検証と、事実との突き合わせは別物**。正規表現を通っただけの値は「読める形をしている」ことしか保証しない。ここに ✅ を書くときは**何と突き合わせているか**まで書く。書けないなら ❌。
  **同じ経路の値が並んだとき、一部だけ ✅ になっていたらそれが指摘**である（上の表がまさにその形で、この列が無かったせいで 1 回目のレビューで 3 行目を取りこぼした）。
- **失敗時の振る舞い** — ここが空欄なら、それは**まだ確かめていない**ということ。
- **記録される理由は事実か** — 止まること自体が正しくても、**止まった理由が事実と違えば、次に動く人は間違った方を直す**。1 つの検査が複数の原因で落ちうるなら、原因ごとに書き分けているか。上の 4 行目がその形で、**この列が無かったせいで、気づいていた指摘が表から落ちて報告に載らなかった**。

### 列は固定ではない — 書けない指摘が出たら列を足す

**上の列は出発点であって完成形ではない。** 実際、`事実と突き合わせているか` も `記録される理由は事実か` も後から足した列で、どちらも同じ壊れ方をしている
— **気づいてはいたのに、表に書く場所が無かったので報告から落ちた**。列を 1 本足すのは 1 回の取りこぼしを塞ぐだけで、次の新しい観点は同じように落ちる。だから規則の側を置く:

> **指摘が既存のどのセルにも書けないと気づいたら、収束を宣言する前に列（または経路表の行）を足す。**

足した列は空欄のまま残さない。**全行を埋め直す。** 新しい列はたいてい、既に埋めたはずの行に空欄を作る — **その空欄が次の指摘**である。

無限に増やさないための、列の条件:

- **1 つの値について答えられる問いであること。** 「この変更は安全か」は列にならない（値ではなく全体の話）。
- **答えが全行で同じになる列は捨てる。** 情報が無く、読む負荷だけが増える。
- **バグクラスは列にしない。** それは §2 の壊れ方か、対象別ファイル（§3）の担当。列は「その値について何を確かめたか」に限る。

### この表が育った経緯

足した理由を消さない。消すと同じ列がまた失われる。

| 足した列 | きっかけ |
| --- | --- |
| 事実と突き合わせているか | 機械可読 3 行のうち検査時刻だけ未検証だったことが、表に現れていなかった |
| 記録される理由は事実か | 「止まるのは正しいが理由が 3 原因で同一」という指摘に、書く場所が無かった（2026-09-06） |

種類の目安:

- 人 / LLM が書いた文書の機械可読行（検査時刻・指紋・対象リスト）
- 別ジョブ・別ステップから渡ってくる事実
- 外部コマンドの出力（`gh api` の JSON、`git` の終了ステータス）
- イベントペイロード（コメント本文、Issue 本文、ラベル、作者）
- リポジトリ / 環境の設定（branch protection、`dependabot.yml`、ラベルの存在、環境変数）
- HTTP レスポンス（ステータス、ボディの形）と、そのパース結果
- 利用者が渡す設定・引数・テナント固有のフィールド定義

### 経路も棚卸しする

入力の表だけでは**制御フローが落ちる**。値の壊れ方は全部当てたのに、その値を扱うループを一度も回していない、という状態になりうる。実際にこれで「収束した」と誤って宣言し、次の回で 2 件出した。**入力は「何を信じているか」、経路は「どこを通ったか」で、別の軸**。

| 経路 | 通したか |
| --- | --- |
| ループを 0 件 / 1 件 / **2 件以上** で回したか | |
| 途中で失敗して打ち切る分岐（残りをどう報告するか） | |
| 上限・予算に当たる分岐 | |
| **dry-run と本番で文言や副作用が変わる分岐**の両方 | |
| 早期 return / 早期 exit のそれぞれ | |

**2 件以上**と **dry-run 側**が特に落ちやすい。前者は単数で動かすと満足してしまうから、後者は本番で走らないので誰も見ないから。実例では、複数 PR のループを一度も回さないまま収束を宣言し、後から「dry-run で中断したときだけ要約が『マージした』と書く」「コメントで同じ番号を 2 回渡すと通る」の 2 件が出た。

## 2. 当てる壊れ方

§1 の各行に、下記 9 つを順に当てる（**この個数を書くのはここだけ**。他のファイルは数を書かずに参照する — 型を足したときに片方だけ古くなるため）。**「当てた」と言えるのは、実行して確かめたときだけ**（[verification-recipes.md][recipes]）。

| 壊れ方 | 問う内容 |
| --- | --- |
| **欠落** | 空だったら？ 取得に失敗したら？ → **空を「問題なし」と読んでいないか**（取得失敗と 0 件を区別できているか） |
| **不正** | 形式が崩れたら？ 大文字 / 全角 / CRLF / 前後の空白は？ |
| **重複** | 2 本あったら？ 読む側が 1 本目しか見ないなら、書く側は 1 本だけを許すべきでは？ |
| **古い** | 前回見た時点と今で変わっていたら？ **その事実は誰がいつ見たものか** |
| **敵対的** | 第三者が同じものを作れるか。作れるとして、何が起きるか |
| **権限** | その主体は本当にそれを**できない状態**か。散文の禁止ではなく、トークンの権限やガードで不可能か |
| **設定変更** | 前提（必須チェック、protection、ラベル、環境変数）が変わったら、**黙って通る**ようにならないか |
| **境界** | 閾値・比較・除算があるなら、**発火する側と発火しない側の両方**を測ったか。整数除算の切り捨て方向（bash は 0 方向）、`>=` と `>`、符号、off-by-one。**閾値を足す修正をしたら、その閾値自体にこれを当てる** — 実例は「未来の検査時刻なら再判定する」ガードで、1 日未満の未来では割り算が 0 になって発火しなかった（1 ケースだけ試して緑にした結果） |
| **自己申告** | その値を**事実と突き合わせたか**。形式が正しいことと内容が正しいことは別で、正規表現を通った値は「読める形をしている」ことしか保証しない。**同じ経路の値のうち一部だけ突き合わせている**状態になっていないか |

**「欠落」が最も多く、最も重い。** 空リスト・取得失敗・読めない行を「該当なし＝問題なし」と読む形は、テストが緑のまま本番で保護だけが消える。

## 3. バグクラス（対象別）

バグクラスの一覧は**対象ごとに分けてある**。変更の種類を判定して、該当するファイルを開く。

| 対象 | ファイル |
| --- | --- |
| シェル / GitHub Actions | [targets/shell-ci.md][shell] |
| TypeScript（ライブラリ本体） | [targets/typescript.md][ts] |

複数の対象にまたがる変更では**全部開く**。対象を足すときの形は [targets/README.md][targets] にある。

§1 と §2 は対象非依存の枠で、どの対象でも同じように使う。**バグクラスをここに書き足さない** — 対象別ファイルが正典で、両方に書くと片方だけ更新されて食い違う。
