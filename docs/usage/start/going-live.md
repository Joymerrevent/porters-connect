# 本番に出す前に

- **前提**: [はじめての書き込み][s4]
- **次に読む**: [目的別の HOWTO][index]（「〜したい」から引く）

ここまでで読み書きはできます。最後に、**本番で効いてくる前提**を 6 つ確認します。
どれも「知らないと、動いてから困る」ものです。

## 1. 機密情報をコミットしない

ホスト名・App ID・App Secret・トークンは**すべて機密情報**です。ホスト名も契約ごとに違うので
公開情報ではありません。`.env.example`（値は空）を雛形に、環境変数で渡してください。

`host` にスキームやパスを混ぜると**構築時に落ちます**。設定ミスで**別のホストを叩く**ほうが
危ないからです。

## 2. どの Partition に書くかを、コードに出す

`tenant(id)` は毎回書きます。既定の Partition はありません。**取り違えた書き込みは消せない**
ので、ここは面倒なほうに倒してあります（[Partition とテナント][partition]）。

複数テナントを 1 プロセスで扱うなら、[マルチテナント][multi-tenant] を読んでください。
テナントごとにカスタム項目の構成が違う場合や、トークンを分けたい場合は client 自体を分けます。

## 3. トークンの置き場所を決める

既定は**インメモリ**です。再起動のたびに取り直します（無人で取り直せるので、動きます）。
プロセスを跨いで共有したい・起動を速くしたいなら `tokenStore` を渡します。**Refresh Token を
外に出す**ことになるので、置き場所の安全性は利用側の責任です（[認証の手順][authenticate]）。

## 4. 上限を知っておく

| 上限                           | どうなるか                                               |
| ------------------------------ | -------------------------------------------------------- |
| リクエスト長 **約 15000 字**   | ライブラリが**送信前に**弾く（PORTERS に届けば 400）     |
| 1 リクエスト **200 件**        | `createMany` / `updateMany` が自動で分割する             |
| 1 分 **Read 2000 / Write 500** | 内蔵スロットリングが自制し、超えそうなら待つ             |
| 月 **約 15 万アクセス**        | **契約条件**。ライブラリは数えません（利用側の運用責務） |

詳しくは[上限][limits]にあります。**月次だけはライブラリの責務にしていません** — プロセスを
跨いだ累積は、ライブラリが正しく数えられないからです。

## 5. 失敗の扱いを決める

`PortersError` の `category` で「落とす／続ける／再送する」を分けられます。

- **`create` は自動で再送されません**（非冪等なので、二重登録になりえます）
- **`auth` 系**は設定か権限付与の問題で、再送しても直りません
- **`network` / レート超過**は待って再送する価値があります

判断表は[失敗の扱い][handle-failures]にあります。

## 6. 差分取得は `P_UpdateDate` で

「前回から更新されたものだけ」は、更新日時の条件で引けます。削除は Connect API からは見えないので、
**消えたレコードを差分で追うことはできません**（`itemstate` で削除済みを読む方法は
[削除 API が無いということ][no-delete]）。

```ts
const updated = await t.candidate.searchAll({
  field: ["P_Id", "P_Name", "P_UpdateDate"],
  condition: { P_UpdateDate: { ge: "2026-09-01T00:00:00Z" } },
});
```

## 出す前のチェックリスト

- [ ] 機密情報が環境変数から来ていて、リポジトリに無い
- [ ] `tenant(id)` の id が、書き込み先として正しい
- [ ] トークンの置き場所を決めた（既定のインメモリで良いかを含めて）
- [ ] 200 件超の書き込みで、**部分成功**をどう扱うか決めた
- [ ] 失敗時に落とすのか続けるのかを決めた
- [ ] 月次アクセス数の見積もりがある
