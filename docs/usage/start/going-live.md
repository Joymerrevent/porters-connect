# 本番に出す前に

- **前提**: [はじめての書き込み][s4]
- **次に読む**: [目次][index]（主題・リソース・用途から引く）

ここまでで読み書きはできます。このページでは、**本番で影響が出る前提**を 6 つ確かめます。どれも「知らないと、
動いてから困る」ものです。終わると、本番に出せる状態になります。

## 1. 機密情報をコミットしない

ホスト名・App ID・App Secret・トークンは**すべて機密情報**です。ホスト名も契約ごとに違うので
公開情報ではありません。環境変数で渡してください（`.env` を使うなら、コミット対象から外します）。

`hostname` にスキーム・パス・ポートを混ぜると**構築時にエラーになります**。設定ミスで**別のホストに接続してしまう**ほうが
危ないからです。

## 2. どの Partition に書くかを、コードに出す

`tenant(id)` は毎回書きます。既定の Partition はありません。**取り違えた書き込みは消せない**
ので、ここは安全なほうに倒してあります（[Partition とテナントスコープ][partition]）。

複数テナントを 1 プロセスで扱うなら、[複数テナント][multi-tenant] を読んでください。
テナントごとにカスタム項目の構成が違うなら、`tenant(id, { fields })` でカスタム項目の宣言（[カスタム項目][custom-fields]）を分けます。client 自体を
分けるのは、トークンを分けたいときだけです。

## 3. トークンの置き場所を決める

既定は**インメモリ**です。再起動のたびに取り直します（無人で取り直せるので、再起動しても止まりません）。
プロセスを跨いで共有したい・起動を速くしたいなら `tokenStore` を渡します。**Refresh Token を
外に出す**ことになるので、置き場所の安全性は利用側の責任です（[認証とトークン][authenticate]）。

## 4. 上限を知っておく

上限は 4 つあり、ライブラリが守るものと、利用側で見るものに分かれます。

| 上限                           | どうなるか                                                            |
| ------------------------------ | --------------------------------------------------------------------- |
| リクエスト長 **約 15000 字**   | ライブラリが**送信前に**弾く（PORTERS に届けば 400）                  |
| 1 リクエスト **200 件**        | `createMany` / `updateMany` が自動で分割する（約 15000 字にも収める） |
| 1 分 **Read 2000 / Write 500** | 内蔵スロットリングが守る。超えそうなら待つ                            |
| 月 **約 15 万アクセス**        | **契約条件**。ライブラリは数えません（利用側の運用責務）              |

詳しくは[上限とレート][limits]にあります。**月あたりのアクセス数だけはライブラリの責務にしていません** — プロセスを
跨いだ累積は、ライブラリが正しく数えられないからです。

## 5. 失敗の扱いを決める

`PortersError` の `category` で「止める／続ける／再送する」を分けられます。

- **届いたか分からない `create` は自動で再送されません**（接続断・タイムアウトなど。非冪等なので、二重登録になりえます）
- **`category` が `auth` のもの**は設定か権限付与の問題で、再送しても直りません
- **`retryable` が `true` のもの**（`category` が `network` / `rateLimit` / `transient` / `server`。レート超過は `network` で届きます）は、
  ライブラリが再試行しても回復しなかったものです。時間をおいて再送する価値があります

判断表は[エラーと再試行][handle-failures]にあります。

## 6. 差分取得は `P_UpdateDate` で

「前回から更新されたものだけ」は、更新日時の条件で引けます。削除されたことは更新日時の差分には現れないので、
**消えたレコードを差分で追うことはできません**（削除済みのレコード自体は `itemstate` の指定で読めます。
[削除と削除済みデータ][no-delete]）。

```ts
for await (const c of t.candidate.searchAll({
  field: ["P_Id", "P_Name", "P_UpdateDate"],
  condition: { P_UpdateDate: { ge: "2026-09-01T00:00:00Z" } },
})) {
  console.log(c.P_Id, c.P_UpdateDate);
}
```

## 出す前のチェックリスト

- [ ] 機密情報が環境変数から来ていて、リポジトリに無い
- [ ] `tenant(id)` の id が、書き込み先として正しい
- [ ] トークンの置き場所を決めた（既定のインメモリで良いかを含めて）
- [ ] 200 件超の書き込みで、**部分成功**をどう扱うか決めた
- [ ] 失敗時に止めるのか続けるのかを決めた
- [ ] 月次アクセス数の見積もりがある
