# 始める前に — PORTERS 側で用意するもの

- **前提**: PORTERS の契約があること（このページはその確認から始めます）
- **次に読む**: [インストールと、クライアントの構築][s-install]

入門は 6 ページあります。上から順に読むと、**自分のアプリが PORTERS に繋がる**ところまで行きます。

このページにコードはありません。このライブラリは **PORTERS 側の準備が済んでいないと 1 行も動かない**
からです。先にここを揃えておくと、次のページから詰まりません。

## 1. 契約を確認する

必要なのは **2 つ**です。どちらか一方では動きません。

| 要るもの                       | 何                                                         |
| ------------------------------ | ---------------------------------------------------------- |
| **PORTERS の契約**             | 製品そのもの                                               |
| **Connect API オプション契約** | API を使うための**別オプション**。これが無いと接続できない |

契約時に**ホスト名・App ID・App Secret** が通知されます。手元に無ければ、まだ次に進めません。

> このライブラリは**非公式**です。ポーターズ株式会社のサポート対象ではありません。
> Connect API そのものの仕様・契約については、PORTERS の窓口に確認してください。

## 2. API アプリを登録して、3 つの値を受け取る

PORTERS 側に**アプリを登録**すると、App ID が発行されます。登録時に **Redirect URL** も決めます
（次のフェーズで使う認可 URL に、登録したものと**同じ値**を渡す必要があります）。

| 値             | 環境変数             | 性質                                             |
| -------------- | -------------------- | ------------------------------------------------ |
| **ホスト名**   | `PORTERS_HOST`       | 契約ごとに違う。**公開情報ではない**             |
| **App ID**     | `PORTERS_APP_ID`     | アプリの識別子                                   |
| **App Secret** | `PORTERS_APP_SECRET` | アプリの認証キー                                 |
| Redirect URL   | —                    | 登録した URL。初回の権限付与で**一致させる**必要 |

**4 つとも機密情報として扱ってください。**ホスト名も契約ごとに違うので公開情報ではありません。
リポジトリにコミットしない運用は [本番に出す前に][s-live] にあります。

## 3. どの Company DB を使うか決める

PORTERS のデータは **Partition（Company DB）**に分かれていて、ほぼすべての操作が
「どの Partition か」を要求します。**対象の Company DB を先に決めておいてください。**

id が分からなくても大丈夫です。繋がった後に一覧を読めます（[認証を通して、疎通を確認する][s-auth]
の最後でそれを使います）。なぜ既定の Partition を持たせない設計なのかは
[Partition（Company DB）とテナント][partition] にあります。

## 4. 付与するスコープを決める

権限は**リソース別に読み／書きが分かれます**（`candidate_r` / `candidate_w` のように）。
初回の権限付与で**まとめて渡す**ので、先に決めておきます。

- **データ系**（`_r` / `_w` あり）: `client` / `recruiter` / `contact` / `job` / `candidate` /
  `resume` / `process` / `activity` / `contract` / `sales` / `phase` / `attachment` / `opportunity`
- **マスタ系**（読み取りのみ）: `partition_r` / `user_r` / `field_r` / `option_r`

**Read でも複数のスコープが要ることがあります。** 例えば Candidate の読み取りには
`candidate_r` に加えて `user_r`・`option_r` が要ります（担当ユーザーや選択肢の項目を取るため）。
リソースごとの正確な必要スコープは[リソース一覧][resources-list]にあります。

**疎通確認のために `partition_r` を入れておいてください。**次のフェーズの最後で、
Company DB の一覧が返ることを「繋がった」の証拠に使います。

## 揃ったかの確認

- [ ] PORTERS 契約 ＋ **Connect API オプション契約**がある
- [ ] API アプリを登録し、**ホスト名・App ID・App Secret** を受け取った
- [ ] **Redirect URL** を登録し、その値を控えている
- [ ] 対象の **Company DB** を決めた
- [ ] 付与する**スコープ**を決めた（`partition_r` を含む）

## まだ揃っていないなら

契約や権限付与を待っている間も、**このライブラリを通るコードは書けます**。PORTERS の代わりに
応答を返す公開ヘルパーがあるので、テストもそのまま書けます —
[契約なしでテストを書きたい][test-without-contract]。

ただし**それは本題ではありません**。揃ったら、このページに戻ってきてください。
