### 1. API 忠実性 — 🔴 [RV-48][rv48]

**気づいた経緯**: 「Read で取れた値を Write に戻せるか（round-trip）」を Option について追った。
Option は read が `string[]`・write も `string[]` で対称（[ADR-0017][adr17]）なので、
その `string[]` が最終的に何になるかを `encodeField` まで降りて確認したところ、
**Option だけが値をテンプレートリテラルに直に埋めてタグ名にしていた**。
他の Data Type はすべて `scalar()`（= `escapeXml`）を経由する。

**なぜカバレッジ 100% で見えなかったか**が今回の収穫。`encode.test.ts` には PCDATA の
エスケープ試験が 3 件あるが、**タグ名側の敵対的入力を試す例が 1 件も無い**。
「値をエスケープしているか」は厚く試験されていて、
「**値がタグ名になる経路がある**」という構造の方が試験されていなかった。
カバレッジは行を通っているので何も言わない。

**重要度の判断**: 🔴 にしたのは 3 点から。(a) 公開型が `string[]` なので **cast 不要**で到達する。
(b) 実測で **well-formed な XML** が生成でき、`<Item>` を注入して別の `P_Id` を名指せた
（`fast-xml-parser` の `XMLValidator` で確認）＝ PORTERS 側が受け付けうる形。
(c) ライブラリの存在理由（XML を隠す）の裏返しが破れている。
**退けた解釈**: 「タグ名だからエスケープすればよい」— これは取れない。`&lt;` は要素名として不正で、
**検証して弾くしかない**。だから修正は挙動変更（要 ADR）になる。

**良かった点**: エスケープの実装自体は正しく、同じ文字列を `SinglelineText` に渡すと
`X/&gt;&lt;/…` と期待どおり無害化される（実測）。穴は 1 箇所で、塞ぎ方も明確。
また `RESOURCE_VALUES`（`resource-list.ts`）は reference の Value 列
（1/3/5/7/9/11/13/17/19/25/27）と**完全一致**し、Phase / Attachment に Value が無いことまで
型（`of("phase")` が compile error）で表現できている。Currency が `Number` に畳まれる扱いも
reference の Data Type 列（FT-14 → Number）どおりで、`order` の対象型に Currency が
無いのは**畳んだ結果として正しい**（一瞬 欠落に見えたが reference を当たって解消した）。

## 良かった点（strengths）

- **フェイルセーフの層が厚い**。送信前ガードが `host` 書式 / `count` 範囲 / `keywords` 長 /
  リクエスト長（URL+body）/ Image の MIME・サイズ / attachment 10MB と**6 系統**そろい、

  [RV-49][rv49] はこの系列の**最後の 1 枚**が欠けているという指摘で、
  逆に言えば残りはすべて埋まっている。
- **「決定した `never`」という書き方**。`ConditionOf` / `WriteValueOfType` を表で書き、
  条件分岐の連鎖を避けたことで「Data Type を足したら**コンパイルが止まって人に決めさせる**」
  構造になっている。`Link: never` に「reference は何も書いていないので狭い側に置く。
  後で広げるのは非破壊なので待つコストは無い」と理由まで残しているのが良い。
- **決定 ↔ 実装 ↔ 台帳の追跡性が 0.8.0 → 0.19.0 でも劣化していない**。ADR 85 本・proposed 0 件、
  前回の指摘 8 件はすべて ADR 化 → accept → 実装 → 公開まで辿れる。
  `pnpm check:index` が索引のズレを CI で落とすので、**人の注意に依存していない**。
- **フェイク ↔ 実装のドリフトが構造的に起きない**設計が、リソース 10 → 17 種でも効いている
  （`test/fake/*` が `src` の descriptor をそのまま使う）。
  `ATTACHMENT_FIELD_NAMES` / `PHASE_DESCRIPTOR` を「in-repo 専用 export」として
  公開 API から外しつつフェイクに共有させる切り分けも維持されている。
