## 観点別所見

### 1. API 忠実性 — 問題なし

この期間の実装は [ADR-0047][adr47]（アクセスポイント / scheme）1 本で、**ワイヤ形状には触れていない**。
`https://${host}` を 10 箇所で組み立てていたのが `apiUrl()` 1 本になり、`grep "https://" src` は
reference の出典 URL しか残らない＝**ホスト名ハードコード禁止がより構造的に守られた**。既定 scheme は `https` で
公開挙動は不変（`access-point.ts:26`）。

前回フェイクで担保した忠実性（OAuth の TTL 単位・XML の非対称・`field` 既定・~15000 字 / 200 件 / レート）は
今回も 503 tests で緑のまま。加えて**フェイクを curl で直接叩く手順書**（`docs/fake-server-runbook.md`）が入り、
「ライブラリの解釈」を介さず reference の形を目視できる経路ができた（全コマンド実行検証済み）。

残るズレはエラー経路の RV-13/14（観点5）で、これは前回から変わっていない。

### 2. アーキテクチャ / ADR 遵守 — 問題なし

ADR-0047 の決定（案B＝`host` ＋ `scheme`）が素直に実装されている。評価点は **URL 組立の集約が先行リファクタとして
分離されている**こと（1 コミット目＝`apiUrl` への集約で公開挙動ゼロ変更、2 コミット目＝`scheme` オプション追加）。
`AccessPoint` を deps に載せる形にしたことで、リソースを足しても scheme 分岐が増えない。
Partition Read だけ `Omit<ResourceDeps, "partition">` にしているのも、partition を取らない API という
[ADR-0022][adr22] の事実を型に落としたもので、逃げの `any` を使っていない。

### 3. コーディング規約（ADR-0013） — 問題なし

新規 2 ファイルとも arrow / `type` / kebab-case。**警告のラッチ（可変状態）を factory
`createInsecureSchemeWarner()` に閉じ込め、プロセス共有インスタンスを 1 つだけ作る**構造は規約どおり
（`insecure-http-warning.ts:36-57`）。`reset()` を「テスト用の seam」と明示して公開 API には出していない点もよい。

### 4. 型安全 / 公開サーフェス — 問題なし

`dist/index.d.ts` への増分は **`Scheme` 型と `PortersClientOptions.scheme` の 2 つだけ**（ADR-0047 の宣言どおり）。
`AccessPoint` は内部に留まり公開されていない。changeset は `minor` で登録済み（`.changeset/access-point-scheme.md`）。

観察（指摘ではない）: `PortersClient.host` は残っているが `scheme` の getter は無いので、
`porters.host` だけでは**アクセスポイントを一意に説明できなくなった**（診断ログ用途では http/https が判らない）。
ADR-0047 が「公開の増分は 2 つだけ」と決めた結果であり、意図的な範囲。必要になったら別途。

### 5. エラーモデル（ADR-0006） — 🟡 RV-13 / 🟡 RV-14 / 🟢 RV-15 / 🟡 RV-17

前回起票の 3 件は **ADR が accepted になっただけで実装は入っていない**（意図どおり＝ADR と実装は別 PR）。
台帳の状態は `open` のままが正しい。

新規 **RV-17** は同じ「エラーが実態と違う顔で出る」系列だが、原因が**入口（設定）側**にある:
`host` は検証されずに `{scheme}://{host}/v1/{path}` へ連結されるため、`PORTERS_HOST` にスキームを含める
（`https://xxxxx.example.com`）という**ありがちな設定ミス**が例外にならず、`https://https://…` という
**それ自体は valid な URL**に化ける。`new URL()` はこれを host=`https` として解釈するので、

- 解決すれば **App ID（OAuth のクエリ）・App Secret（Token の body）が意図しないホストへ実際に送られる**、
- 解決しなければ `fetch-transport.ts:29-33` により `retryable: true` の `PortersNetworkError` になり、
  **直しようのない設定ミスをリトライで叩き続ける**（`category` も `config` ではなく `network`）。

空文字（`PORTERS_HOST` 未設定を `!` で押し通した場合）は宛先が **`v1`** になる。いずれも実測で確認した。
docs 側（README・`.env.example`・ADR-0047）は正しく「ホスト＋ポートのみ」と書いており、**足りないのは強制**。
ライブラリは既に長さ 15000 字・Attachment 10MB を送信前に落としているので、その系列に
「アクセスポイントの書式」を 1 つ足すのが自然。ADR-0047 で scheme が独立した今、
`host` の意味は前より厳密に決まっている＝いま検証を足すのに適したタイミング。

## 良かった点（strengths）

- **「許可と沈黙を分ける」がコードで表現されている**: `scheme: "http"` は繋ぐ許可であって黙る許可ではなく、
  黙らせるのは専用 env だけ。しかも `""`/`0`/`false` では黙らず、env で抑止したときは
  **latch を立てない**（`insecure-http-warning.ts:40-42`）ので、env を外した次のクライアントにはちゃんと届く。
  「曖昧な値で静かにならない」という設計判断がコメント付きで残っている。
- **ループバックを免除しなかった**こと。「localhost なら安全」は一見親切だが、
  ローカルのフェイクと TLS を失った本番は設定からは区別できない＝免除は静かな事故を作る。
- **リファクタと機能追加を別コミットに割った**（URL 集約 → scheme 追加）。前者は公開挙動ゼロ変更で、
  レビューと二分探索の単位が正しい。
- **手順書が実測で書かれている**（`docs/fake-server-runbook.md`）。「生 UTF-8 クエリは Node の HTTP パーサが
  400 を返す」「レート超過は 429 でなく切断」など、**実行しないと分からない罠**が記録されている。
