## 観点別所見

### 1. API 忠実性 — 問題なし（関連: 🟢 [RV-16][rv16]）

この期間の主作業（[ADR-0043][adr43] フェイクサーバー フェーズ0〜5）は、実質**忠実性の再監査**として機能した。
フェイクは `docs/reference` を正として XML ワイヤ形状・独自 OAuth・制約を再現し、**ライブラリの実物**（`PortersClient`）を
それに対して駆動する。結果、以下は実測で担保された:

- **OAuth**: `code_direct` の envelope・**code 30 秒失効**・単回使用・トークン TTL が**ミリ秒**（`token.md`）・
  refresh 失効時の再取得（ADR-0036）まで往復（`test/fake/oauth.test.ts` ほか）。
- **XML の非対称性**: User は ID で Write・入れ子で Read／Option は裸 alias で Write・`<OptionRoot>` で Read／
  System[Reference] は ID 往復／DateTime は ISO⇄PORTERS（`test/integration/field-types.test.ts` が全 Data Type を1本で網羅）。
- **Read の `field` 既定**（ADR-0020）: フェイクは「要求された field だけ返す」ため、既定 field を送らなければ
  `P_Id` しか返らないという本番挙動がテストで再現される。RV-1 の罠が**構造的に**再発しない形になった。
- **制約**: ~15000 字 → 400／200 件超 → 102／1 分 Read 2000・Write 500 → 強制切断、を両側（送信前ガードとサーバ拒否）で検証
  （`test/integration/constraints.test.ts`）。スロットル既定値も正典と一致（`throttle.ts:43-44`）。
- **削除 API 不在**: store に delete が無く、HTTP アダプタは DELETE に 405 を返す＝「無いものを作らない」を構造で担保。
- **ホスト名ハードコードなし**（`https://${host}` のみ）。

ズレとして残るのは**エラー経路の 2 件（RV-13/14）**で、これは観点5 に記す。
また月次クォータの記述だけが実態より強い（RV-16・観点7）。

### 2. アーキテクチャ / ADR 遵守 — 問題なし

- **ADR-0043 の決定どおり**に実装されている: in-repo・dev-only（`test/fake/`＝`src/` の外）、`files` は `dist` のみで
  **tarball 非同梱**、coverage 対象外（include=`src/**`）、しかし**フェイク自身のテストは書く**（7 ファイル）。
- **層分離は維持**。フェイク側も同じ層構成（protocol / state / wire / query / oauth）で写像され、XML は `wire.ts` に閉じている。
  `src/resources/` に XML は漏れていない。
- **src への変更は descriptor の export のみ**（`CANDIDATE_/JOB_/CLIENT_/PROCESS_/RESUME_/PARTITION_/USER_/FIELD_/OPTION_DESCRIPTOR`・
  `ATTACHMENT_FIELD_NAMES`・`RESOURCE_VALUE`）。これは ADR-0043「D-fixture 共有＝ワイヤ形状はライブラリを単一ソースに」の
  直接の実装であり、**カタログの写しを作らない**ための最小変更。`ResourceConfig` を `ResourceDescriptor` ＋ `requiredOnCreate` に
  分解した点も、既存の型契約を壊していない。

### 3. コーディング規約（ADR-0013） — 問題なし

- 追加コードは全て arrow / `type` / kebab-case。新規 class なし。`any` の散布なし（XML は `asRecord`/`asString` で narrowing）。
- **lint の適用範囲が広がった**: フェーズ0 で `test/tsconfig.json` を追加し、`pnpm typecheck` が `tsc --noEmit && tsc -p test` に。
  型付き lint（projectService）も test/ を対象にできるようになった＝フェイクも規約の外に置かれていない。

### 4. 型安全 / 公開サーフェス — 問題なし

- `dist/index.d.ts` の export 一覧は**変化なし**。追加した descriptor 群は d.ts に一切現れない（`grep -c DESCRIPTOR` = 0）。
- `RESOURCE_VALUE` は d.ts に `declare const`（非 export）として現れるが、これは**以前から公開されている** `ResourceType`
  （`keyof typeof RESOURCE_VALUE`）を成立させるための内部宣言で、export 面の変化ではない。
- 公開 API 不変＝この期間のリリースは不要（changeset なしで運用してきた判断と整合）。

### 5. エラーモデル（ADR-0006） — 🟡 [RV-13][rv13] / 🟡 [RV-14][rv14] / 🟢 [RV-15][rv15]

**この run 固有の観察**: フェイクが「忠実度の強制関数」として働き、**普段のテストでは踏まない経路**を
3 つまとめて露出させた（[RV-13][rv13] / [RV-14][rv14] / [RV-15][rv15]）。単体テストは自分が用意した応答しか
返さないので、**エラー経路は「作ってみて初めて分かる」**という構造的な性質がある。フェイクを作った副産物として
出てきた 3 件で、狙って探したものではない。

**処置の方針**: いずれも「動くが将来困る」種で、**挙動変更を伴うため実装前に決める**必要がある。
まとめて 1 本の ADR にせず、**1 判断 1 ADR** で [ADR-0044][adr44]（HTTP ステータス）・
[ADR-0045][adr45]（Write ルート `<Code>`）・[ADR-0046][adr46]（例外契約）へ分けて起票した。
指摘の詳細は台帳の各ファイルを参照。

なお [RV-14][rv14] は**エラー時にルート `<Code>` が本当に出るのか自体が未確認**なので、
[live-verification][lv] LV-11 の確認が前提になる（仮定の上に実装しない）。
`category: "rateLimit"` が未 produce のまま（RV-3 で結論済み）である点は変わらないが、
**[RV-13][rv13] を直せば HTTP 429 経由で produce しうる**ので ADR-0044 の論点に含める。

- 488 tests・カバレッジ perFile 100/98.75・Stryker 96.84%（break 95）。**閾値の実質的な引き上げは無いが、質は変わった**:
  従来の単体中心から、**実クライアントを駆動する L1 結合**（`test/integration/**`）が加わった。
- **fixture と実挙動の乖離リスクは下がった**。フェイクは fixture を置き換えるのではなく、
  `test/fake/errors.test.ts` が「フェイクの出力 ↔ reference の fixture」を突き合わせる形にしてあるため、
  どちらかがズレれば落ちる。result code 28 件・認証エラー 17 件を全件検証。
- **注意（指摘ではない）**: フェイク自体は coverage / mutation の対象外なので、`src` のカバレッジ 100% は
  もはや「単体で厳密」を意味しない（結合テストでも埋まる）。厳密性の実質的な担保は **Stryker** 側にある。
  フェイクの正しさは自前の 7 テストファイルと fixture 突き合わせで担保している。

### 7. ドキュメント / DX — 🟢 [RV-16][rv16]

- README は**非公式明示・契約必須注記・対応バージョン（[ADR-0042][adr42]）**を保持。リンクは参照スタイル。
- **RV-16**: 月次クォータ（約15万/月）を「内蔵スロットリングで分散」と書いているが、`throttle.ts` は 1 分バケットのみ。
  月次は**契約条件**であり、プロセス横断の累積管理はライブラリの責務ではない（薄いラッパー）。
  記述を「1 分上限は自制／月次は運用責務」に書き分けるのが妥当。実装変更は不要。
- **エラーハンドリング ガイドに「非 PORTERS ボディの HTTP エラー」の項が無い**。これは RV-13 の症状そのものなので、
  RV-13 の是正とセットで追記するのが自然（本レビューでは RV-13 に含め、別 finding にはしない）。
- `live-verification.md` は LV-9〜12 が増え、`grep -rn "VERIFY(live)" src test` と表の対応が保たれている（フェーズ4 で棚卸し済み）。
- CONTRIBUTING に**モック / フェイクの使い分け表**と `pnpm fake:serve` の手順が入り、新規貢献者が迷わない形になった。

## 良かった点（strengths）

- **フェイクが「忠実度の強制関数」として実際に機能した**。RV-13/14/15 はいずれも、実 API を叩けない状況で
  仕様と実装のズレを炙り出した成果。ADR-0043 が期待した効果がそのまま出ている。
- **フェイルセーフの実装が一貫している**: 未実装ルート → `PortersConfigError`／HTTP では 501、PORTERS が使わない verb → 405、
  強制切断 → 実際にソケットを destroy、未配線オプション → 構築時に拒否。「渡したのに何も起きない」を作らない設計。
- **役目を終えた仕掛けを撤去している**（`WIRED_FAULT_KINDS` → フェーズ1、`WIRED_OPTIONS` → フェーズ4）。
  死んだ分岐を残さない判断は、テスト可能性の観点でも正しい。
- **単一ソース化の徹底**: フェイクはカタログの写しを持たず、ライブラリの descriptor を import する。
  Attachment だけは写しが要るが、`wiring.test.ts` にドリフト検知テストを置いて逃げ道を塞いでいる。
