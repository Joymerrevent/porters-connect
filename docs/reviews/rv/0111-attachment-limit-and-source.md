# RV-111 🟢 添付ファイルの上限が 10MiB より約 19,000 文字多く、出典が reference に無い

- 重要度: 🟢 ／ 観点: API 忠実性
- 状態: fixed

## 概要

上限 14,000,000 文字は、10MiB の Base64（13,981,016 文字）より大きい。10MB と FileName 255 バイトの出典は ADR-0018 だけで、reference に無い。

## 根拠

- `src/porters/attachment.ts:7`。実測（サブエージェント）: 13,981,020 文字は送られた。

## 影響

🟢。PORTERS 側で拒まれるとみられる。

## 検出経緯

2026-09-26 に `src` のすべてのコード（テストを除く 121 ファイル）を change-review の手順でレビューした。http・auth／xml・util／accessor／resources・fields・クライアントの 4 つのまとまりに分けて並行で調べ、High と主な Medium は、報告の前に別の試験で再現を確かめた。

## 推奨

- デコード後のバイト数で数え、出典を LV に登録する。
- 止めどきの規則（Low だけになったら直さずに記録する）により、この回では直さずに記録する。

## 処置

**実施（2026-09-27・fix/fields-attachment-low-review・`c1a242f`）。** ユーザーの判断で、値は ADR-0018 のまま変えず、10MB が何の単位か（10,000,000 バイトか 10 MiB か、デコード後のバイト数か）を LV-38 に登録した。コードに VERIFY(live) を書いた。出典については、再レビューで、上限（10MB）・ファイル名（255 バイト）・Windows で使えない文字が Attachment - Write の記事にあると分かった。欠けていたのはリポジトリ内の reference の要約だけなので、要約に「新規登録と更新の注意点」を足した。ファイル名の 255 バイトと使えない文字は、ライブラリでは確かめていない（PORTERS がエラーを返す）。

## 検証

`pnpm check:lv`（LV-38 とコードの対応）。
