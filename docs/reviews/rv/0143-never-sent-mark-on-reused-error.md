# RV-143 🟢 Transport が同じエラーの実体を使い回すと、送らずに失敗した印が送った後の失敗に漏れる

- 重要度: 🟢 ／ 観点: フェイルセーフ
- 状態: open

## 概要

印はエラーの実体に付く。自作の Transport が同じ `PortersError`（再試行しない server / unknown）を使い回し、あるリクエストのトークンの取得で投げた後、`createMany` の送信済みの create でも同じ実体を投げると、一括書き込みが「書き込まれていない」と判断して、「書き込まれた可能性がある」の案内が消える。

## 根拠

- `src/http/requester.ts` の `NEVER_SENT`、`src/accessor/write-many.ts` の `knownNotWritten`。実測（再レビュー・2026-09-27）。

## 影響

🟢。エラーの実体を使い回す Transport という作為的な条件でだけ起きる。自動では再送しない。

## 検出経緯

2026-09-27 のアクセサの軽微な指摘の修正（fix/accessor-low-review）を、change-review の手順でレビューし直したときに見つけた。止めどきの規則により、この回では直さずに記録する。

## 推奨

- 送った後に捕まえたエラーも別の WeakSet に記録し、「送らずに失敗した印があり、送った後の記録が無い」ときだけ書き込まれていないと判断する。
- 止めどきの規則（Low だけになったら直さずに記録する）により、この回では直さずに記録する。
