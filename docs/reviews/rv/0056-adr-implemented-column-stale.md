# RV-56 🟢 ADR 索引の「実装」列が 0.8.0 以降更新されず、凡例が 21 本で事実と食い違う

- 重要度: 🟢 ／ 観点: ドキュメント / プロセス
- 状態: fixed

## 概要

`docs/adr/index.md` の「実装」列は「その決定がどの版で世に出たか」で、`—` は凡例が
「プロセス決定で実装の概念が無いもの、または MVP 期に段階的に実装され CHANGELOG が版を明示
していないもの」と説明する。しかし **ADR-0055 以降、CHANGELOG が版を明示している設計 ADR 21 本**
に `- Implemented:` が無く、索引は全部 `—`。凡例の説明はこの 21 本には当てはまらない。
最後に記入されたのは ADR-0051（0.8.0・2026-08）。

## 根拠

- `docs/adr/index.md:9-11` — 凡例（`—` の意味と「記入は CHANGELOG が版を明示している分に限る」）。
- ADR 本文: ADR-0044〜0051 は `- Implemented: 0.7.0` / `0.8.0` を持つ
  （例 `docs/adr/0044-http-status-handling.md:6`）。**ADR-0055〜0086 は 1 本も持たない**（grep 実測）。

## 影響

🟢・ドキュメントの正確さ。索引を読む人は ADR-0085 の `—` を「特定の版に紐づけていない」と読むが、
実際は 0.19.1 で出ている。「決定 ↔ 実装 ↔ 台帳 ↔ 公開」の追跡性はこのプロジェクトの強み
（[2026-09-18-01][run] の良かった点）で、その**最後の一段（公開版）が索引から消えかけている**。
版が知りたければ CHANGELOG を grep すれば分かるので実害は小さいが、**凡例が事実と違う**のは
直す価値がある。[RV-18][rv18]（roadmap から ADR 実装が見えない）と同じ類型。

## 検出経緯

観点2（ADR 遵守）で ADR-0085 / 0086 の反映を確認する際、索引の「実装」列が両方 `—` なのに
CHANGELOG 0.19.1 / 0.20.0 が番号で名指ししていることに気づき、0044 以降を全数突合した。

## 推奨

- (a) 21 本に CHANGELOG から `- Implemented:` を転記する（機械的に決まる。複数版に跨る 0055 / 0073 は
  最初の版）。索引の列も同時に直す（`pnpm check:index` が片側だけの変更を落とす）。
- (b) 再発防止は 2 択。(b1) release runbook／release スキルに「CHANGELOG に ADR 番号を書いたら
  本文に `Implemented` を入れる」を 1 行足す。(b2) `check:release` に「CHANGELOG の版節で名指し
  された**基本設計／詳細設計**の ADR に `Implemented` が無ければ落とす」を足す（0060 のように
  方向を示すだけの言及があるので、フェーズで絞る）。人の記憶より仕組み（CLAUDE.md）なら (b2)。
- (c) 書かないと決めるなら、凡例を「0.8.0 までの記入」に書き換えて列を凍結する
  （書かないなら約束しない）。

いずれも **ADR 不要**（[ADR-0053][adr53] の運用の範囲）。

## 処置

**完了（案 (a) ＋ (b2)・2026-09-21）。**

- **(a) 21 本に `- Implemented:` を転記し、索引の列も直した。** 値は CHANGELOG の版節が
  **最初に**名指しした版（0055 → 0.10.0・0073 → 0.15.0）。指摘の表と同じ 21 本で、それ以外の
  ADR には触っていない（0060 は要件定義・0068 はプロセス＝実装の概念が無い側。0083 は CHANGELOG が
  名指ししていないので凡例どおり空欄のまま）。
- **(b2) `check:release` に検査を 1 つ足した**（`scripts/check-release-invariants.mjs` の
  `checkAdrImplemented`）。**0053 より後の基本設計／詳細設計 ADR**について、索引の「実装」が
  「CHANGELOG の版節が最初に名指しした版（名指しが無ければ `—`）」と一致するかを見る。
  - **0053 で区切る根拠**: [ADR-0053][adr53] が列を導入したとき、既知分（〜0051）は遡って記入し、
    MVP 期の決定は「空欄のまま」と決めた。0053 より後の ADR は列の運用が始まってから生まれたもの。
    0019 / 0020 のように後の版が**文脈として**挙げる MVP 期 ADR を誤検知しないための境界でもある
    （実測: 0.9.0 の CHANGELOG が ADR-0019 / 0020 を挙げるが、実装は 0.1.0 以前）。
  - **フェーズで絞る根拠**: 推奨どおり。0060（要件定義）は 0.12.0〜0.14.0 で 4 回名指しされるが
    「方向」の ADR で実装の版は無い。フェーズは索引のヘッダ見出しで列を探すので、列の並びが変わっても
    壊れない。索引が読めない・行が 0 本のときは**エラーにする**（黙って通すと検査が一度も走らない）。
  - **`[Unreleased]` は数えない**。リリース PR で版節に変わった瞬間に、その版が名指しした ADR の
    記入漏れが落ちる＝ runbook の手順と同じタイミングで効く。
  - 期待値を「**最初の**版」にしたのは、後の版が同じ ADR を改訂の文脈で挙げることがあるため
    （0073 は 0.15.0 で実装・0.18.0 でバケットの単位が変わった）。
- **runbook §1 に手順を 1 行**（CHANGELOG に名指しした設計 ADR には `Implemented` を書く・検査が落とす旨）。
  索引の凡例にも検査の存在を 1 項目。CI の `check:release` のコメントにも 1 行。
- **ADR は起こしていない**（推奨どおり [ADR-0053][adr53] の運用の範囲。列の意味も任意性も変えず、
  「0053 より後の設計 ADR は CHANGELOG が名指ししたら書く」を検査で担保しただけ）。

## 検証

- **検査を develop の索引（修正前）に当てると、指摘の 21 本がそのまま落ちる**ことを実測した
  （`ADR-0055（基本設計）は CHANGELOG 0.10.0 が名指ししているのに「実装」が空です …` × 21）。
  転記後は 0 件。転記後の索引で 0086 を空に戻す／0073 を 0.18.0 にする／0083 に 0.18.0 を書く、
  の 3 通りも 1 件ずつ落ちる（それぞれ「空」「最初の版と食い違う」「名指しされていない版」の文言）。
- `scripts/check-release-invariants.test.mjs` に 14 件（25 → **39 件**）: 名指しの収集（最初の版・
  素の表記・`[Unreleased]` と前書きは数えない）／索引の読み取り（列の並び替え・列が無い）／
  検査本体（通る形・空・後の版・名指し無し・`[Unreleased]`・0053 以前・設計以外・索引が読めない）／
  `checkRelease` 経由で「`[Unreleased]` が版節になった瞬間に落ちる」。
- `pnpm check:index` は転記後も一致（本文と索引を同時に直した）。品質ゲートは全 green。
