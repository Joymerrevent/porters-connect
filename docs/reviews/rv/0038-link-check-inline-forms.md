# RV-38 🟢 リンク検査が inline リンクの一部を見ない

- 重要度: 🟢 ／ 観点: ドキュメント / フェイルセーフ
- 状態: open

## 概要

`pnpm check:links`（[`scripts/check-doc-links.mjs`][script]）が拾う inline リンクは
**`./` / `../` で始まるものだけ**。`[x](guide.md)` のように相対パスを直接書いた形と、
`[x](./guide.md "Title")` のようにタイトルが付いた形は**検査されないまま通る**。

## 根拠

- 実測（2026-09-12）: 仕込んだ `[x](missing6.md)` と `[x](./missing7.md "title")` は
  どちらも報告されなかった（参照スタイルの定義側は同じ日に 3 形へ拡張済み）。
- **広げると誤検出になる**ことも実測した。`./` を要求しない正規表現にすると、
  リンクではない散文 2 箇所（`](…)` と `]([Field Alias],[Field Alias]...)`）を
  リンク先として拾う。**取りこぼしと誤検出のどちらを取るかの選択**であり、
  今は「誤検出を出さない」側を選んでいる。

## 影響

**小さい。** inline リンクは markdownlint の `MD054`（`inline: false` / `url_inline: false`）が
そもそも禁止しているので、人が書く文書では lint が先に落とす。`MD054` の対象外は
`CHANGELOG.md` と `.changeset/`・`docs/api/`（生成物）だけで、そこに書かれる**相対**リンクは
実測 0 件（外部 URL のみ）。つまり現在の実害は無く、`MD054` を緩めたときに初めて効く。

## 検出経緯

change-review（2026-09-12、`docs/concepts-pages`）。記法 12 通りの受理/棄却表を実データに
当てて見つけた 3 つの取りこぼしのうち、**唯一直さなかったもの**。他の 2 つ（タイトル付き定義・
3 字下げの定義）は誤検出の危険が無かったので同じ変更で塞いだ。

## 推奨

`MD054` を緩める判断をするとき、または `.changeset` / `CHANGELOG.md` に相対リンクを
書き始めたときに、この穴を塞ぐ。塞ぐなら「リンクとして成立する形」（拡張子つき、または
リポジトリ内に実在する綴り）に限定して拾い、散文を巻き込まないこと。

## 処置

**止めどきの規則により見送り**（`.claude/skills/change-review/SKILL.md` §7 — 🟢 だけの指摘は
直さず記録する。修正は新しいコードなので再レビューを呼び、ループが終わらなくなるため）。
今回は 🟡 と同じファイルに集中していた 🟢 5 件を相乗りで直したが、**この 1 件だけは
誤検出とのトレードオフがあるので意図的に残した**。
