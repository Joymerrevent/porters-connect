# RV-144 🟢 Code 5 を auth にしたので、一括書き込みが「書き込まれていない」と判断するが、処理の前に断る応答かは確かめていない

- 重要度: 🟢 ／ 観点: フェイルセーフ
- 状態: open

## 概要

`createMany` の 2 つ目以降のバッチが Code 5 で失敗すると、`auth` は断られたことがはっきりしている分類なので、そのバッチを「書き込まれていない」と案内する（以前は「書き込まれた可能性がある」）。Code 5（ユーザー ID 無効）が処理の前に断る応答だというのは、reference の意味からの推測。

## 根拠

- `src/accessor/write-many.ts` の `REFUSED_CATEGORIES`、`src/errors/resource-error.ts`。1 つ目のバッチは実測、2 つ目以降は読んだだけ（再レビュー・2026-09-27）。

## 影響

🟢。Code 5 が処理の途中で返ることがあれば、利用者が書き込まれたレコードを再送して重複を作りうる。起きるのはユーザー ID が無効なときだけ。

## 検出経緯

2026-09-27 の ADR-0106 の実装（feat/adr-0106-unknown-outcome-and-codes）を、change-review の手順でレビューし直したときに見つけた。止めどきの規則により、この回では直さずに記録する。

## 推奨

- 実機で Code 5 の後にレコードが作られていないことを確かめる（LV に登録する）。確かめられるまでは、一括書き込みでは Code 5 を「書き込まれた可能性がある」側に倒すことも考える。
- 止めどきの規則（Low だけになったら直さずに記録する）により、この回では直さずに記録する。
