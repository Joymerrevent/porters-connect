# RV-40 🟢 リンク検査がインラインコードスパン内のリンクを誤検出する

- 重要度: 🟢 ／ 観点: ドキュメント / DX
- 状態: fixed

## 概要

`pnpm check:links`（[`scripts/check-doc-links.mjs`][script]）は**コードフェンスの中**を
検査対象から外すが、**インラインのコードスパン**（バッククォート 1 組）は外さない。
リンクの書き方を説明する文章が、**説明しただけで壊れリンクとして報告される**。

## 根拠

実測（2026-09-12）。次の 1 行だけの md を置くと、存在しない `./gone.md` を指す
壊れリンクとして報告される（フェンスで囲めば報告されない）:

```md
説明: `[x](./gone.md)` のように書くと inline リンクになります。
```

参照スタイルの定義側は無事。定義の正規表現が行頭の `[` を要求するので、
バッククォートで始まる行には当たらない。**inline リンクの正規表現だけが行のどこでも走る**。

## 影響

**安全側（フェイルクローズ）。** 誤検出なので見逃しではなく、赤くなって気づく。
ただし直し方が「リンクではないものをリンクだと言われる」形なので、書き手はフェンスへ
逃がすか表現を変えることになり、**説明のための引用が書きにくい**。

現に [RV-38][rv38] は**1 文字差でこれを踏むところだった** — 引用した 2 例が
`./` を持たない形と空白を挟む形で、どちらかが正規形なら台帳を足した瞬間に CI が赤くなっていた。

## 検出経緯

change-review 2 巡目（2026-09-12）。1 巡目でコードフェンスの除外を入れた**その修正が
残した穴**で、RV-38 のニアミスから見つけた。修正が新しい指摘を生む典型
（`.claude/skills/change-review/SKILL.md` §7 の「止めどき」が想定している形）。

## 推奨

行を走査する前にインラインコードスパンを落とす。バッククォートの対応付けは
フェンスと同じ考え方（同じ長さのバッククォート列で閉じる）で足りる。
**フェンスの追跡と同じ関数の中で完結する**ので、着手するならフェンス処理の隣に置く。

## 処置

**塞いだ**（2026-09-15）。推奨どおりフェンス追跡の隣に置き、行を走査する前にインラインの
コードスパンを潰す。対応付けの考え方もフェンスと同じ（開いたのと**同じ長さ**の
バッククォート列で閉じる）＝入れ子（` ` で ` を囲む形）でも開閉が逆転しない。

中身は**空白に置換**する。列の位置が動かないので、同じ行の**外**にあるリンクや行頭の
`[label]:` 定義はそのまま拾える（潰し方で別の穴を作らない）。閉じが無いバッククォートは
コードスパンとして扱わない — 1 個のバッククォートで**以降のリンクが黙って消える**ほうが
誤検出より悪いため。

## 検証

テスト（[RV-41][rv41]）に 4 ケース。「説明のための引用が報告されない」ことと、
そのために**別の見逃しを作っていない**こと（同じ行の外のリンク・タイトル内のコードスパン・
閉じていないバッククォート・入れ子）を両方固定した。`pnpm check:links` は緑（205 ファイル）。
