# RV-18 🟢 accept 済み ADR の実装が roadmap に現れない

- 重要度: 🟢 ／ 観点: ドキュメント / 計画
- 状態: fixed

## 概要

[ADR-0044][adr44] / [ADR-0045][adr45] / [ADR-0046][adr46] は accepted（実装は別 PR）だったが、
roadmap の「いま着手」には**案A（MCP）とフェイク フェーズ7 しか無かった**。
台帳を読まないと「**決まっているが未実装の挙動変更が 3 件ある**」ことが計画上見えない。

## 根拠

- `docs/roadmap.md:18-26` — 「いま着手」に案A・案C フェーズ7 のみ。
- `docs/adr/README.md:112-115` — 「実装順序は 0044 → 0045」「0046 は独立して着手可」と
  **実装順序まで決まっている**。
- 台帳の [RV-13][rv13] / [RV-14][rv14] / [RV-15][rv15] はいずれも `open`。

## 影響

ADR 運用（起票 → accepted → **実装** → docs → リリース）の**最後の 3 工程が計画の正典から抜け落ちる**。
roadmap は「次に何をやるか」を判断する入口なので、そこに無い作業は忘れられる。
実際 3 件とも accept から実装まで日が空いた。
ドキュメントの穴なので 🟢 だが、**計画の信頼性**に直結する。

## 検出経緯

[2026-08-10-01][run810]。ADR の索引を読んでいて、
accepted 済みの決定が実装順序まで決まっているのに roadmap から辿れないと気づいた。
**ドキュメント観点の指摘だが実体は計画の穴**。

## 推奨

roadmap の「いま着手」に 1 行足す — 「**エラーモデルの是正**（ADR-0044 → 0045 → 0046 の実装・RV-13/14/15）」。
実装内容は ADR と台帳が正なので、roadmap 側は**ポインタのみ**でよい（重複させない）。

## 処置

推奨（1 行追加）を超えて、**roadmap を TODO の入口として作り直した**（stakeholder 提案）。
先頭に「▶️ いま何をやるか」を新設し、**着手可能 / 随時・任意 / 待ち**の 3 区分と
「**TODO の見取り図**」（どのファイルに何の TODO があり何件か）を置いた。

## 検証

ADR-0044 → 0045 → 0046 / 0048 の実装が「着手可能」の表に**順番・根拠・semver つき**で載り、
**roadmap だけを見れば着手できる**状態になったことを確認。
併せて陳腐化していた記述（ADR 件数・テスト数・open の RV 一覧・LV の範囲・PRD §8 の残論点）も実態へ是正した。
内容は ADR と台帳が正＝roadmap 側はポインタのみ（重複させない）を維持している。
