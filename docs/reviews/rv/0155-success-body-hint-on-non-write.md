# RV-155 🟢 2xx でない成功の応答の hint が、読み取りと認証の経路でも書き込みの案内になる

- 重要度: 🟢 ／ 観点: エラーモデル / DX
- 状態: fixed

## 概要

`successBodyStatusError` の hint は「書き込みを繰り返す前にレコードを読み直す」と案内する。読み取りや、OAuth / Token のやり取り（`default-token-provider` / `exchange-token`）で同じ応答が届いたときも、同じ hint が付く。

## 根拠

- `src/errors/http-status-error.ts` の `successBodyStatusError`。分類と再試行の動きは実行して確認済み、認証経路の hint の文面は読んだだけ（再レビュー・2026-09-27）。

## 影響

🟢。分類と再試行の動きは正しく、案内の文面が経路に合わないだけ。実機の PORTERS が 2xx 以外で成功の本文を返すかは未確認（LV-9）。

## 検出経緯

2026-09-27 の RV-153・RV-154 の修正（fix/rv-153-154）を、change-review の手順でレビューし直したときに見つけた。止めどきの規則により、この回では直さずに記録する。

## 推奨

- 経路（書き込み・読み取り・認証）に合わせて hint を分けるかを決める。
- 止めどきの規則（Low だけになったら直さずに記録する）により、この回では直さずに記録する。

## 処置

**実施（2026-09-27・fix/rv-155-156・`4366053`）。** `successBodyStatusError` の hint を、どの経路にも合う文面（status と本文が食い違い、結果が分からない。API の手前の中間装置を確かめる）にした。送った create には、requester の `asUnknownOutcome` が結果の分からない書き込みの案内を足す（302 は後ろに続け、503 は置き換える）。一括書き込みは、バッチの案内が同じことを伝える。読み取りのエラーに書き込みの案内が付かないことをテストで確かめる。
