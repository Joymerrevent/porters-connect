# RV-35 🟢 未来の検査時刻を弾くガードが 1 日未満の未来で発火しない

- 重要度: 🟢 ／ 観点: フェイルセーフ
- 状態: open

## 概要

追跡 Issue の検査時刻が未来だと再判定に倒すガードは、**1 日以上未来のときしか発火しない**。
整数除算が 0 方向に切り捨てるため、23 時間後までは経過日数が 0 になる。

## 根拠

- `.github/scripts/dependabot-triage-gate.sh` — `age_days` は秒差を 86400 で割った整数で、
  bash の除算は**0 方向に切り捨てる**（`-43200 / 86400 = 0`、`-86400 / 86400 = -1`。実測）。
  よって `[ "$age_days" -lt 0 ]` は 25 時間後から成立する。
- 実測（2026-09-06、偽 gh ＋ ミラーツリーで gate を実行）:
  +1h / +12h / +23h は `should_run=false`、+25h / +10d / +400d で発火。
- 元の指摘は「未来の検査時刻で 3 日ルールが恒久的に無効化される」で、その修正として
  このガードを入れた（`a9242cb`）。**危険な形は塞がっている**が、範囲が想定より狭い。

## 影響

**恒久ロックは防げている。** 抑止が永久に続くには指紋が変わらないまま大きく未来の値が要り、
そこは発火する（400 日後で確認）。1 日未満の未来で起きるのは**最大 1 日の再判定の遅れ**だけで、
実時間が追いつけば自己解消するので 🟢。

到達には write 権限を持つ人が Issue 本文を編集する必要がある（投稿側は未来の時刻を弾くので、
このワークフローが自分で書くことはない）。

## 検出経緯

change-review 2 巡目（2026-09-06）。**自分が前のラウンドで入れた修正**を、発火する側だけ
1 ケース試して緑にしていたのが原因。この教訓から `breakage-matrix.md` §2 に
9 番目の壊れ方「**境界**」（閾値を足したら発火する側と発火しない側の両方を測る）を足した。

## 推奨

日数ではなく epoch を直接比べる: `[ "$prev_epoch" -gt "$(date -u +%s)" ]`。
どんな未来値でも実行に倒れて単純になる。投稿側が許す +10 分の余裕分が引っかかっても、
「迷ったら走らせる」方向なので無害。

## 処置

RV-34 と同じく、change-review の**止めどきの規則**により見送り。
