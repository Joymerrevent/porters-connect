# RV-34 🟢 取り込み時の同一性チェックが 3 つの別原因を同じ文言で報告する

- 重要度: 🟢 ／ 観点: フェイルセーフ / DX
- 状態: open

## 概要

`/merge` が「判定したときと同じコミットか」を確かめる祖先判定は、**原因が違っても同じ
メッセージ**を出す。止める判断は 3 つとも正しいが、**記録される理由が事実と違う**ケースがある。

## 根拠

- `.github/scripts/dependabot-merge.sh:227` — `git merge-base --is-ancestor "$judged" "$head"` は
  次のいずれでも非ゼロを返す:
  (a) 本当の force-push、(b) **`$head` がローカルクローンに無い**（checkout 後に push された）、
  (c) `$head` が空 / 不正。
- 出力は (a) だけを名指しする:
  「判定した時点のコミット X がこの PR の履歴にありません（**force-push で中身が入れ替わった可能性**）」。
- 実測（2026-09-06）: 実リポジトリで `$head` を「ローカルに無い正当な形の SHA」「空文字」に差し替え、
  使い捨て repo で作った**本物の force-push** と 3 つ並べて、**同一文言**になることを確認した。
- [ADR-0065][adr65] 論点2 の追記は、この検査を「判断は判定表として既に出ている」を成り立たせる
  ための仕組みと位置づけている。仕組みは効いているが、失敗の説明が対応していない。

## 影響

**動作は安全側。** どのケースでも取り込みは止まり、利用者への指示（判定をやり直す）も正しい。
壊れているのは理由だけなので 🟢。

ただし (b) は起こりうる — `/merge` は複数 PR を最大 45 分かけて回すので、その間に後続 PR へ
push が入る窓がある。さらに (b) では `$head` を解決できない時点で「**判定の後に積まれたコミット**」の
検査（`rev-list`）に到達しないため、本来そちらで説明されるケースまで force-push として報告される。
放置しても壊れないが、原因追跡のときに間違った方を疑う。

## 検出経緯

change-review 2 巡目（2026-09-06）。検証ハーネス自身の `cut -d= -f2` バグが空の `$head` を渡したのが
発端で、そこから意図的に 3 ケースを再現した。**整合的に作った偽物では踏めなかった経路**で、
この教訓は `.claude/skills/change-review/references/targets/shell-ci.md` の狙い2 に反映済み。

## 推奨

祖先判定の前に `git cat-file -e "${head}^{commit}"` を挟み、解決できないときは
「checkout 後に push された可能性」と書き分ける。同じブランチは既に同じ理由で
待ち時間の打ち切り理由を上限ごとに書き分けている（`c59d772`）ので、その基準に揃える。

## 処置

change-review の**止めどきの規則**（🟢 Low だけのラウンドは直さず記録して終える。
`.claude/skills/change-review/SKILL.md` §7）により見送り。修正は新しいコードとして
再レビューを呼ぶため、Low を直し続けるとループが終わらないという判断による。
