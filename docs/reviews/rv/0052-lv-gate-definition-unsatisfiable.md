# RV-52 🟢 `1.0.0` の条件 V5 が定義上満たせず、LV の件数表記も実態とずれている

- 重要度: 🟢 ／ 観点: ドキュメント / 計画
- 状態: open

## 概要

[roadmap][rm] の `1.0.0` 完成条件 **V5** は「[live-verification][lv] の**全エントリ**が
『状態: **確定**』」と定めているが、LV には `確定` にはならない状態（`解消`）のエントリが
既に 2 件ある。**V5 は文言どおりには永久に満たせない**。あわせて「LV-1〜25 が未確認」
「V5 = 0 / 25」という件数表記が、実態（`確定` 1 件・`解消` 2 件）とずれている。

## 根拠

[live-verification][lv] のサマリー表（実測）:

| LV    | 状態                                                 |
| ----- | ---------------------------------------------------- |
| LV-3  | `解消`（[ADR-0081][adr81] が仮定そのものを無くした） |
| LV-4  | `解消`（同上）                                       |
| LV-5  | `確定`                                               |
| 他 22 | `未確認`                                             |

対して [roadmap][rm]:

- `docs/roadmap.md:53` — `| V5 | … | 全エントリが「状態: **確定**」 | **0 / 25**（契約待ち）|`
  → LV-5 が既に `確定` なので **0 件ではない**。さらに LV-3 / LV-4 は
  `解消` で止まる（確認する対象が消えたため）＝ **25 / 25 には構造的に到達しない**。
- `docs/roadmap.md:272` — 「LV-1〜25 が未確認（契約待ち）」→ 3 件について誤り。
- `docs/roadmap.md:552` — 「**LV-1〜25**」も同じ数え方。

[live-verification][lv] 自身の運用節は「確定しても**エントリは削除しない**。『状態』を `確定` に
変え…」と書くだけで、**`解消` という状態の存在と、それを件数にどう数えるかを定義していない**
（`解消` は ADR-0081 の作業中に実地で生まれた状態）。ここが食い違いの源。

## 影響

`1.0.0` は「契約後のライブ検証が終わったら」と定義されていて、V5 がその判定器。
判定器が満たせない形だと、**リリース可否の判断が文言では下せず、毎回人の解釈に戻る**。
実害が出るのは契約が取れた後なので **latent**、かつ読み替えれば意味は通る（`解消` は
「確認不要になった」）ので 🟢。

ただし放置すると 2 つの形で効く:

- **件数が指標として使えなくなる**。[ADR-0084][adr84] で成功指標を「数値目標を置かず
  マイルストーンで測る」に決めた以上、残っている数え上げ（`0 / 25`）は正確でないと
  進捗ビューとして機能しない。今回のように毎回レビューで突き合わせ直す手間になる。
- **`解消` を「確定」に書き換える誘惑**が生まれる（V5 を緑にするため）。それは
  「確認した」と「確認が不要になった」を混ぜることで、[live-verification][lv] が
  区別のために作った状態を壊す。

## 検出経緯

[roadmap][rm] の V4 の測り方を実行して確かめる作業（[RV-50][rv50]）の途中で、
V5 の分母も見に行ったのがきっかけ。V4 を grep で検証したあと「同じ表の隣の行は
どう測るのか」を読んだら、**分母 25 に `解消` が混ざっている**ことに気づいた。
LV 表を上から読むだけでは `解消` が 2 件しかないので見落としやすく、
**roadmap 側の数字と突き合わせて初めて**ずれが出た。

## 推奨

挙動変更は無いので ADR は不要。文言の整備のみ。

1. **[live-verification][lv] に状態の定義を 1 節足す**: `未確認` / `確定` / `解消` の 3 値と、
   `解消` は「仮定そのものが無くなった（ADR で設計が変わった）」であって
   「確認して合っていた」ではないこと。どちらも**これ以上やることが無い**点は同じ。
2. **V5 を「`未確認` が 0 件」に書き換える**。`解消` も `確定` も終端状態なので、
   これなら到達可能で、意味も変わらない。現在地は `22 / 25 が未確認` のように書く。
3. `docs/roadmap.md:272` / `:552` の「LV-1〜25 が未確認」を実数に直す。
   ただし**毎回手で数え直す形にはしない** — [RV-50][rv50] の推奨 3（LV 検査スクリプト）に
   状態ごとの件数を出させ、roadmap は「検査が出す数」を参照する形にできると腐らない。
