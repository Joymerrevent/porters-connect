# RV-39 🟢 リンク検査が見出しアンカーの実在を見ない

- 重要度: 🟢 ／ 観点: ドキュメント
- 状態: fixed

## 概要

`pnpm check:links`（[`scripts/check-doc-links.mjs`][script]）は `path#anchor` の
**ファイル部分しか見ない**。リンク先のファイルさえあれば、`#` 以降の見出しが無くなっていても
通る。見出しはリファクタで最も変わりやすい部分なので、**ファイルより先にアンカーが腐る**。

## 根拠

- `scripts/check-doc-links.mjs` — `target.split("#")[0]` でアンカーを捨ててから実在を見る。
  スクリプト冒頭にも「アンカー付きのパスはファイル部分だけ見る」と明記してある（既知の範囲外）。
- 実測（2026-09-12）: アンカー付きの相対リンク定義は **5 件**。うち 4 件は同一ページ内
  （`[do]: #decision-outcome` など）、**1 件が別ファイルの見出しを指す**
  （`[lv16]: ../live-verification.md#lv-16-…`）。
- 同一ページ内アンカー（`#` だけで始まる形）は、ファイル部分が空なので**そもそも検査に入らない**。

## 影響

**小さいが、消えるときに音がしない。** 壊れたアンカーは GitHub 上ではページ先頭に飛ぶだけで
404 にならないため、読者も書き手も気づかない。件数が 5 件と少ないうちは手で追えるが、
`docs/index.md` を起点にした 4 層構成（[ADR-0070][adr70]）でページ間参照が増えると効いてくる。

## 検出経緯

change-review（2026-09-12、`docs/concepts-pages`）。リンク検査そのものを棚卸ししたときに、
「見ていないと書いてあるが、見ていないことの影響を測っていない」項目として拾った。

## 推奨

対象ファイルの見出しから GitHub 互換の slug（小文字化・空白をハイフン・記号除去・日本語はそのまま）を
作り、`#` 以降と突き合わせる。**同一ページ内アンカーも同じ経路で検査できる**（ファイル部分が
空なら自分自身を見る）。slug 生成の規則は GitHub 実装に依存するので、突き合わせに失敗したときは
**落とさずに一覧で報告する**ところから始めるのが安全（誤検出で赤くするとゲートが外される）。

## 処置

**塞いだ**（2026-09-15）。推奨どおり、対象ファイルの見出しから GitHub 互換の slug を作って
`#` 以降と突き合わせる。**同一ページ内アンカーも同じ経路**（ファイル部分が空なら自分自身を見る）
＝従来そもそも検査に入っていなかった 4 件も対象になった。

推奨は「まず落とさずに一覧で報告する」だったが、**落とす側にした**。「slug 生成は GitHub の
実装に依存する」という当てにくさは、**リポジトリに実在するアンカー 8 件すべてで突合できた**ことで
解消している。規則の要点は「ASCII の句読点を落としてから空白を 1 つずつ `-` にする」順序で、
`#lv-17-…-項目を--付きで…` の**二重ハイフン**がその順序の証拠（`` `()` `` を落とした跡に
空白 2 つが残る）。

そのうえで**拾う側は広く倒した** — 怖いのは見逃しではなく誤検出（赤くするとゲートが外される）なので:

- setext 見出し（`===` / `---`）も拾う。表の区切りやフロントマターを拾いうるが、
  余分な slug は「通りやすくなる」だけで、**見逃しは検査が無かった元の状態と同じ**にしかならない
- 明示アンカー（`<a id="…">` / `<a name="…">`）も宛先として認める
- percent-encoded なアンカーは復号して突き合わせる
- 見出しを持たないもの（md 以外・ディレクトリ指し）は見ない

落ちたときは**先頭一致が最長の見出しを候補として出す**（見出しは「少し変わる」のが普通なので、
直しに往復が要らない）。

## 検証

**検査が効くことを確かめた**（緑を見て済ませていない）。実在するアンカーを 2 箇所
（別ファイル向け・同一ページ内）一時的に 1 文字ずらすと、両方が候補つきで報告された:

```text
見出しが見つかりません（2 件）。ファイルはありますが、`#` 以降の見出しがありません:
  README.md:166 -> docs/usage/index.md#リソースと操作ズレ（近い見出し: #リソースと操作）
  docs/live-verification.md:416 -> #lv-3-attachment-の-get-条件ズレ（近い見出し: #lv-3-attachment-の-get-条件）
```

戻したあとは緑（205 ファイル）。受理/棄却は [RV-41][rv41] のテストに 11 ケース足してある
（slug 規則・重複見出しの `-1`・フェンス内の `#` を見出しにしない・md 以外は見ない など）。
