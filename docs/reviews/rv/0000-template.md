## 根拠

<`file:line` と、正典（`docs/reference/` / ADR / PRD）の該当箇所を**対にして**書く。
「コードのこの行がこう書いてあり、正典はこう定めている」の形。再現・追跡できない指摘は価値が低い。
実測して確かめたなら、その入力と結果も書く（例: 空文字を渡すと宛先が `v1` になる）。>

## 影響

<**なぜその重要度なのか**。放置すると誰が何に困るか、いつ発火するか（今すぐ壊れる / latent）。
「動くが将来困る」と「今すぐ壊れる」を混同しない。ここが薄いと、後から重要度の妥当性を検証できない。
例: 基本的な read が空に見え、このライブラリの第一価値（型付きレコード）が既定経路で崩れる＝実用ブロッカー級。>
